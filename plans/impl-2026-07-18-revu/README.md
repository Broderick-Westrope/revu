# Revu Implementation Plan

> **Status:** COMPLETED

## Overview

Revu is a VS Code extension (Cursor-compatible) that unifies human-in-the-loop code review: an LLM-generated **guided review** (themed file groups, suggested order, commentary — generated by shelling out to an agent CLI) and **local review comments** (native Comments API, stored in `workspaceState`, exported as AI-friendly markdown to the clipboard). GitHub PR threads render inline read-only via `gh`; the extension never writes to GitHub.

Spec: `plans/design-2026-07-18-review-extension.md`.

Phased because the work spans four independently reviewable subsystems: extension scaffold + git diff core, the comments engine, agent-CLI guide generation, and GitHub read-only integration.

## Phases

| # | File | Delivers | Depends on | Review focus |
|---|------|----------|------------|--------------|
| 1 | `phase-1-core.md` | Extension scaffold, scope picker, git diff engine, base-ref content provider, native diff opening | — | Git edge cases (renames, deletes, untracked, degenerate branch scope), URI scheme design |
| 2 | `phase-2-comments.md` (parallel) | Local comments via Comments API, workspaceState persistence, markdown clipboard export | Phase 1 | Comment data model, export format fidelity, thread restore on reload |
| 3 | `phase-3-guide.md` (parallel) | Agent CLI invocation, guide JSON contract, sidebar tree view, caching + staleness | Phase 1 | Prompt/JSON contract robustness, truncation strategy, cache keying |
| 4 | `phase-4-github.md` | `gh` PR metadata + review threads, read-only inline rendering, quote-to-local-comment, export integration | Phases 1–3 | Read-only guarantees, GraphQL pagination, naive anchoring trade-offs |

> Phases 2 and 3 share no code beyond Phase 1's git/scope module and can be developed and merged in either order.

## Phase Boundaries

- **1 → 2/3:** Phase 1 isolates all git plumbing and the scope model so both the comments engine and the guide build on a stable `ReviewScope` + changed-files API.
- **2 → 4:** GitHub threads reuse the comment-rendering patterns and extend the export format with quoted threads; the local comment model must be settled first.
- **3 → 4:** Guide generation consumes PR title/description when available; Phase 4 wires `gh` metadata into the existing prompt builder (small, contained change noted in Phase 4).

## Review Notes

Devils-advocate review (2 rounds on spec, 1 on plan) caught and fixed: GraphQL `--paginate` emits one merged JSON doc (not concatenated pages); `revu.createComment` menu entry needs `"group": "inline"` to render as the Submit button; `thread.comments` must be reassigned, not pushed; `gh repo view --json owner` returns a nested object (use `nameWithOwner`); fence-aware guide JSON extraction; skip restoring comments on deleted files; documented that out-of-editor file changes don't trigger the stale indicator until save/refresh.
